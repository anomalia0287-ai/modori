**Goal:** Seal and run an offline, synthetic, independently verifiable Windows kit that measures the complete live Research OS waits on the same low-cost HP office laptop, enforces the approved 30-second p95 and 100-millisecond UI-acknowledgement gates without averaging stages together, and produces the final evidence-backed go/stop disposition.

A deterministic outer ZIP, sidecar, embedded bootstrap digests, closed manifest, canonical result schema, and independent result verifier surround that runtime.

**Tech Stack:** Python 3.12.10; existing PyInstaller Windows toolchain; PySide6/QCoreApplication; the committed Research OS/Research Memory/Research Flow/calculation code; canonical JSON and SHA-256; PowerShell 5.1-compatible bootstrap; pytest; Ruff; Bandit.

## Frozen measurement protocol

### Acceptance fixture

The deterministic fixture is `modori.live_research_os.office_fixture.v1`:

- 50,000 ordered rows by 40 ordered columns = 2,000,000 cells;
- 16 SCALE numeric columns, including independent outcome, paired before/after,
  Pearson pair, and additional finite/missing variants;
- 8 ORDINAL columns, including the Spearman pair;
- 8 NOMINAL columns, including an exactly two-level group;
- 4 Boolean columns and 2 date columns with stable typed encodings;
- 2 NFC-normalized text columns used only to exercise fingerprint typing;
- deterministic missing masks, finite values, nonzero variances, adequate group sizes,
  paired differences, variable metadata, and source-schema descriptor; and
- no random seed, file import, or wall-clock value. Values are generated by fixed
  index-based formulas and the complete fixture digest is asserted.

This size is frozen before target measurement because it represents a demanding but
bounded wide social-science table, exercises every supported profile in one identity,
and stays materially below the separate 5,000,000-cell resource ceiling.

All six profiles use fixed variable IDs from this one fixture. A separate 5,000,000-cell
stress fixture checks cancellation/resource behaviour but is explicitly non-acceptance:
it may reveal a limit, but cannot rescue or fail the frozen 2,000,000-cell result.

### Repetitions and strata

- **Cold series:** 20 fresh identity-only child processes plus 20 fresh scenario child
  processes for **each** of the six profiles (140 fresh processes total). Each child
  builds the fixture before the timer. Identity children take one full identity sample;
  each scenario child walks only its designated profile through a fresh task and every
  required later answer round, so no profile is made artificially warm by its position
  after another profile.
- **Warm series:** 30 complete in-process iterations after one untimed warm-up. Every
  iteration performs an uncached full fingerprint for the identity row, then fresh task
  allocation/initial decision and later rounds while reusing only the exact fingerprint
  where the product contract permits it.
- Every profile therefore has at least 20 cold and 30 warm observations for initial
  decision. Every actual later round is reported by profile and round ordinal; the
  overall later-row p95 includes all valid later-round observations, and acceptance also
  requires every profile/round p95 to pass.
- Main-thread acknowledgement is measured for every public P1 action in both cold and
  warm series from call entry until the busy/static state signal is observable. Worker
  completion is not part of this row.
- Human reading/answer time, fixture generation, process import/startup, result
  serialization, and cleanup are outside the timed waits and reported separately.

### Result contract

The canonical result uses schema ID `modori.live_research_os_office_benchmark`, version
1, and contains only:

```text
run_id
recorded_at_utc | null
source_commit
kit_identity_digest
protocol_digest
fixture identity, digest, dimensions, and declared column-kind counts
closed execution-condition evidence
coarse non-identifying hardware/OS/storage evidence
all raw duration observations in integer nanoseconds
per-series/profile/round nearest-rank p95 values
main-thread acknowledgement observations
peak working set and bounded resource observations
closed error/reason codes
recomputed evaluation
result_hash
```

`result_hash` is SHA-256 over the canonical result object with `result_hash` omitted.
The `.json.sha256` sidecar hashes the final canonical JSON bytes. The Korean summary is
generated only from the verified parsed result and is not an authority source. Hardware
evidence excludes hostname, username, device/volume serial, MAC/IP, exact user path,
installed-app inventory, and file names.

`run_id` is a fresh closed UUID used only to bind child observations and output names.
`recorded_at_utc` is optional display metadata from an injected UTC clock; neither field
changes thresholds, ordering, authority, or evaluation, and local-time fallback is
forbidden.

## Final decision semantics

- **Go:** every local/product/kit/mutation gate passes and every valid HP subgroup meets
  the frozen timing/acknowledgement threshold. The UI remains experimental and never
  auto-runs.
- **Invalid run:** transport, checksum, path, power, runtime, schema, observation, or
  protocol evidence is invalid. Fix only the rational setup cause and rerun unchanged.
- **Stop:** a valid target or product gate remains failed after one focused repair. Keep
  the deterministic core and direct analysis, but do not expose the live P1 path.

Passing this plan still establishes no human gold, recommendation accuracy, statistical
validity, numerical equivalence, causal validity, general SPSS superiority, or secure
erasure.
